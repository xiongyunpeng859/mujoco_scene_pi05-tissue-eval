## 最重要的一件事：看画面顶部的横幅

**这个环境的 OpenCV 是 headless 构建，弹不出窗口**（`cv2.imshow` 报
"The function is not implemented"）。程序检测到之后会**自动改成浏览器界面**，
你不需要手动加 `--web`。启动后终端会打印：

```
浏览器打开 http://127.0.0.1:8765
```

用**浏览器**打开这个地址就是界面。两种打开方式：

- **在主机自己的桌面（NoMachine）上**：直接开 Firefox/Chromium，访问 `http://127.0.0.1:8765`
- **在你自己的 Windows 电脑上**（推荐）：先建 SSH 隧道，再开本地浏览器

  ```powershell
  C:\Putty\plink.exe -ssh -L 8765:127.0.0.1:8765 -pw 521521 fmc3-6@192.168.1.104
  ```

  这个窗口别关（它就是隧道），然后本地浏览器打开 `http://127.0.0.1:8765`。
  PuTTY 图形界面：`Connection → SSH → Tunnels`，Source `8765`，Destination
  `127.0.0.1:8765`，Add，再连 `192.168.1.104`。

> 跑程序的终端必须一直开着——网页的画面是那个进程实时推流出来的。

页面顶部有一个**很大的状态条**，画面顶部也有一条同样的横幅：

| 显示 | 含义 |
|---|---|
| 🟩 **OK - PRESS S TO SAVE**（绿底 + 对勾） | **现在可以拍**，按 `s` 保存 |
| 🟥 **NOT READY - DO NOT SAVE**（红底 + 叉号） | **现在还不能拍**，按了也不会保存 |
| 🟧 **NO JOINT DATA - NOT USABLE**（橙底 + 竖线） | **读不到关节角**，拍了也不能做手眼标定 |
| 🟦 **PREVIEW ONLY - NOT SAVED**（蓝底 + 方块） | 预览模式，**不保存** |

判定要求**连续 3 帧都合格**才变绿，所以不会来回闪。看到绿了再按 `s`。

（横幅文字用英文，是因为 OpenCV 的 Hershey 字体**画不了中文**，会渲染成 `?????`；
所以配了语言无关的对勾/叉图标。）

### ⚠ 关节角是**硬要求**，不是可选字段

手眼标定解的是 `T_base_tag = T_base_eef @ T_eef_camera @ T_camera_tag`，
其中 `T_base_eef` **只能来自当时的 6 个关节角**。所以：

- **`--preview` 不保存照片。** 它本来就不连机械臂，关掉 SAVE 按钮是应该的。
  预览只有一个用途：调姿态、确认棋盘格能被检测到。
- **`--capture` 默认要求机械臂可用**：连不上会**直接退出**，不会"优雅降级"成
  一批没有关节角、做不了标定的废数据。确实只想拍相机内参才用 `--no-arm`。
- 每次保存时如果关节角缺失，终端会打印
  `⚠ 这张没有关节角 —— 不能用于手眼标定`。
- 会话文件里的 `mode` / `arm_connected` 字段记录了当时的模式，事后可查。

程序不在画面上列原因，也不在终端刷屏。终端各只说一句：
`✅ 已保存 sample_003（共 3 张）` 或 `⛔ 现在还不能拍 —— 这张没有保存`。
被拒照片的详细原因写进 `rejected.jsonl`，要排查时再看。

### 机械臂会不会被锁住 —— 会，这是模式决定的

| 模式 | 电机 | 手推 | 说明 |
|---|---|---|---|
| 默认（只读） | 上电 + **PVT 位置保持** | ❌ 推不动 | 读关节角的代价；臂刚性锁在当前姿态 |
| `--free-drive` | 上电 + **MIT 自由拖动** | ✅ 可以推 | **无重力补偿，臂会因自重缓慢下坠**，必须用手托着 |

这套 SDK 只有 `INVALID / MIT / CSP / CSV / PVT`，**没有重力补偿模式**，所以"手推"
只能靠 MIT。`--free-drive` 里默认加了关节阻尼（`--free-damping 1.0`，0 = 纯零力矩），
比纯零力矩下坠慢、更稳，但仍然抵消不了重力。

**想用手摆姿态就用 `--free-drive`。** 锁定时若想解锁：先**托住机械臂**，
再 `Ctrl+C` 退出程序（退出会 `disable()`，电机变软、臂会掉）。

### 中途重启不会丢数据

重启用**同一个 `--session` 目录**即可续上，已有的样本会读回来、从下一个编号继续：

```bash
$PY capture_hand_eye_dataset.py --capture --free-drive --cols 11 --rows 8 --square-mm 15 \
  --session outputs/calibration/hand_eye_left_realsense_20260918_062627
```

启动时会打印 `↻ 续用已有会话：已恢复 N 个有效样本，继续往上加`。

红底**最常见的原因**（按经验排序）：

1. **棋盘格没有整块进入画面**（板被画面边缘切断）—— 最常发生，把机械臂挪一下
2. 画面模糊 / 太暗
3. 板太正对镜头（倾角太小，这种姿态对手眼标定没贡献）
4. 与已有样本的关节位姿太接近（没有新信息）

`--preview` 模式下不连机械臂，所以"有没有关节角"不参与判定，只判画面质量。

## 1. 你的棋盘格参数（已确认）

| 项 | 值 |
|---|---|
| 方格数 | **12 × 9 格**（长边 12 格） |
| **内角点数** | **11 × 8 = 88 个**（内角点 = 方格数 − 1） |
| 方格边长 | **1.5 cm = 15 mm** |
| 打印区尺寸 | 12 × 1.5 = **18 cm** × 9 × 1.5 = **13.5 cm** |

**所以命令用：**

```bash
$PY capture_hand_eye_dataset.py --preview --board checkerboard --cols 11 --rows 8 --square-mm 15
```

`--cols 8 --rows 11` 也一样（两者只差一个板内 90° 旋转，是固定变换，会被
`T_eef_camera` 吸收，只要整个会话保持一致就行）。

> ⚠️ **别再用 `--cols 6 --rows 7`。** 之前自动探测报 6×7，是因为板只露出一部分、
> 检测器锁在了 11×8 大板里的一个 6×7 子窗口上（6≤11、7≤8）。用 6×7 会在板
> 完整可见时直接检测失败。
>
> 启动时如果看到这样的提示，就是板没拍全，必须重摆姿态：
>
> ```
> ! 还命中了更大的规格 11x8：画面里的板很可能只露出一部分，检测器锁在了大板里的一个子窗口上。
> ```

### 摆姿态的实际要求

板是 18 × 13.5 cm，D405 在 640×480 下 `fx≈394`。板在画面里的像素宽度 ≈
`394 × 0.18 / 距离(m)`：

| 相机到板的距离 | 板占画面宽 |
|---|---|
| 0.25 m | ~284 px |
| 0.40 m | ~177 px |
| 0.60 m | ~118 px |

正常工作距离（0.3–0.5 m）下板只占 150–240 px，**不难拍全，关键是别让板贴到画面边缘**。
判定要求四周至少留 20 px 余量：看预览里那个**绿色多边形**，它要完整闭合地贴住
棋盘格外沿、不碰画面边框。

## 2. 正式采集

### 方式 A：只读关节角 + 手动摆位（推荐先试这个）

```bash
$PY capture_hand_eye_dataset.py --capture --board checkerboard --cols 11 --rows 8 --square-mm 15
```

程序**只读** 6 个关节角，不下发任何运动指令。用遥操作/手推把机械臂摆到能
**完整**看到棋盘格的姿态，等横幅变绿，按：

```
s        保存（红底时按了不会保存）
d        删除刚保存的上一张
c        样本 ≥ 3 时求解并退出
q / Esc  退出，已保存的样本保留
```

### 方式 B：零力矩手推（危险）

```bash
$PY capture_hand_eye_dataset.py --capture --free-drive --cols 11 --rows 8 --square-mm 15
```

MIT 零力矩**没有重力补偿，机械臂会因自重下落**。程序会先提示你托住机械臂、
按回车才进入自由拖动。必须确认急停可用、周围无人无障碍。

### 方式 C：连不上机械臂也能先存图

```bash
$PY capture_hand_eye_dataset.py --capture --no-arm --cols 11 --rows 8 --square-mm 15
```

（只能用于相机内参/预览，没有关节角做不了手眼。）

### 采样要求

- 至少 **15 张**，每张 = 一张图 + 当时的 6 个关节角
- **必须有明显的腕部转动**（左右/上下/前后倾斜**和**绕光轴旋转）。
  只平移不转是解不出来的 —— 结束时程序会明确告诉你"几乎没有相对旋转"
- 相邻样本的关节差异要大于 `0.05 rad`，否则会判为"和已有样本太接近"而变红
- 想强行保存判红的照片，加 `--save-any`（原因会一起记下来）

## 3. 求解

采集时按 `c`，或事后：

```bash
$PY capture_hand_eye_dataset.py --solve --session outputs/calibration/hand_eye_left_realsense_<时间戳>
```

输出 `T_eef_camera.yaml`，含 `T_eef_camera`、样本数、方法、残差。程序会做**两层
异常帧检测**，并在终端明确告诉你剔掉了哪些帧、为什么：

1. **自洽性检验（不需要知道 X）**：手眼关系要求任意两帧之间 EEF 的相对旋转角
   必须等于标定板的相对旋转角。对不上的帧就是异常帧。
   *典型原因*：板被挪过，或那一帧的关节角与图像不是同一时刻。
2. **残差精修**：若某帧旋转一致、只有平移偏大，那是**标定板被平移过**的特征
   （板的平移不改变任何相对旋转）。这种帧也可以剔。

然后程序会打印**尺度自检**：

```
相机相对 EEF 的位置 = [-30.0, 51.7, 121.8] mm，距法兰 135.6 mm
```

- **平移残差 RMS > 10 mm 就别用**（本机实测：40 帧全用=25.4mm，剔 1 帧=4.6mm，
  再精修=2.8mm）
- 判读要点：**相机位置对样本选择是否稳定**。本机实测在剔帧过程中只在
  135.2~136.7 mm 之间游走（±1mm），说明结果可靠
- 如果"距法兰"不在 **20–150 mm** 范围内，程序会警告——这几乎一定是 `--square-mm`
  填错了

> **为什么方格边长必须实测：** 它填错会让整个标定的**尺度线性缩放**，
> 而残差照样很小、完全看不出来。所以只能用"相机到法兰的距离是否合理"来兜底。
> 你的板是 15 mm，直接填 `15` 就行。

## 4. 中央相机内参标定（--calibrate-camera）

中央（顶置）相机是**固定在支架上不动的**，所以标定它只能**移动标定板**——
这正是 `cv2.calibrateCamera` 的标准做法（它解的是"板相对相机的一系列位姿"，
相机动还是板动完全等价）。

```bash
$PY capture_hand_eye_dataset.py --calibrate-camera --web --port 8765 \
  --cols 11 --rows 8 --square-mm 15
```

（不指定 `--camera` 时，这个模式默认用 `uvc`，即顶置的 LRCP 500W。）

### 怎么拍

1. **把板举到镜头前 25~40 cm**，正面对着镜头。
   ⚠️ 不要把板平放在桌上拍 —— 那样板在画面里只有约 50px 宽、每格 4~5px，完全标不准。

   | 板到镜头距离 | 板在画面里的像素宽 | 每格像素 |
   |---|---|---|
   | 1.5 m（放桌上） | ~50 px | 4.5 px ❌ |
   | 0.5 m | ~150 px | 13 px ⚠️ |
   | **0.35 m** | **~213 px** | **19 px** ✅ |
   | 0.25 m | ~300 px | 27 px ✅ |

2. 横幅变绿后按 `s`。每存一张，终端会打印 **4×4 覆盖网格**：

   ```
   ##  ..  ##  ..
   ##  ##  ..  ##
   ..  ##  ##  ..
   ##  ..  ##  ##
   ```

   画面上还会实时显示板落在哪一格、这一格拍过没有：

   ```
   cell (1, 2)  NEW CELL - good                  ← 新格子，可以拍
   cell (1, 2)  COVERED - move to a new cell     ← 这一格拍过了，挪走
   ```

   如果板离已有视图太近而被拒绝，终端会直接告诉你该挪到哪里，例如
   `建议挪到：左上(0,0)、右上(3,0)、左下(0,3)、右下(3,3)  共剩 14 格`

3. **把板移到画面里还没被覆盖的位置**再拍。**四个角一定要拍到** ——
   畸变系数和主点完全靠边缘/角落的角点约束出来。
4. 变化距离（让板在画面里时大时小）和倾角（有时正对、有时明显倾斜）。
   结束时程序会检查：板像素跨度变化、倾角变化是否够大，不够会明确提示。
5. 目标：**≥ 15 个视图，覆盖 ≥ 7/16 格**。
6. 按 `c` 求解。

> 中途重启不丢数据：`--calibrate-camera --session <同一个目录>` 会读回
> `views.json`，从下一个编号继续。

### 这个模式的判据与手眼不同

- **不需要机械臂、不需要关节角**（相机固定）
- **允许、而且需要**接近正对镜头的视角（手眼那边反而要避免正对）
- 手持会抖，所以**不算晃动**，改为"连拍 2 帧取最清晰的一帧"+ 靠锐度与重投影误差把关

### 什么时候会判"可以拍"

一张要**满足**下面两条之一：

1. **给画面覆盖新增格子** —— 覆盖按"板角点占到的区域"算（不是板中心），
   所以同一位置把板**拿近**让角点伸到更外围，也算新增；
2. **画面覆盖已经够了（≥10/16 格）时**，只要和已有视图有明显差异：
   **板在画面里的宽度差 ≥15%**（≈距离变化 15% 以上）**或倾角差 ≥10°**。

两条都不满足才会判红，画面上会写清楚是哪一条不满足：

```
cells +2 new (total 14)                      ← 新增了 2 格，可以拍
cells +0 new (total 14)   ok: tilt diversity ← 靠倾角差异通过
cells +0 new (total 14)   MOVE SIDEWAYS or change DISTANCE/TILT
why: change DISTANCE or TILT - area already covered
```

> **注意**：内参标定**不是**"必须凑够 15 张"。求解器 **≥8 张就能算**，
> 15 只是建议值。覆盖和多样性够了就按 `c`，先解一版看残差。

### 输出

`camera_intrinsics.yaml`：

```yaml
fx / fy / cx / cy
camera_matrix: [[fx,0,cx],[0,fy,cy],[0,0,1]]
distortion_coefficients: [k1,k2,p1,p2,k3]
rms_reprojection_px: ...        # 整体重投影 RMS，> 0.5px 就偏差大了
per_view: [...]                  # 每个视图的误差，可看出哪张拍坏了
fov_deg: {vertical: ..., horizontal: ...}
adequacy: {...}                  # 视图数 / 覆盖格数 / 倾角与距离范围
```

MuJoCo 里可直接用 `focalpixel="fx fy"` + `principalpixel="w/2-cx h/2-cy"`，或用 `fovy`。

事后重算：`--solve-intrinsics --session <目录>`

## 关键约定（很重要，别改）

1. **`T_eef_camera` 的 EEF 坐标系是 `link6`**，由厂商 `play_e2.urdf` 的正运动学给出。
   已实测验证：该 FK 与 MuJoCo 生成模型里 `link6` 的 body 位姿**一致到 1e-6**。
   所以这个结果**可以直接放进 MuJoCo 场景**，不需要任何坐标换算。

2. **不要用项目里的 `mmk2_kdl_py.ArmKdlNumerical`**（自带的
   `calibrate_o10_wrist_hand_eye.py` 用的是它）。实测它和这条臂的 URDF **不等价**：
   `ArmKdlNumerical(arm_type="play_short", eef_type="none")` 相对 `link6`
   旋转差约 177°、平移随位姿漂移 0.4~0.9 m。它算出的 `T_base_eef` 与本工具的
   **不是同一个坐标系**，两者结果不能混用。
   （现有右腕标定 `o10_right_wrist_hand_eye.yaml` 平移 RMS 29.6 mm 偏大，可能与此有关。）

3. **棋盘格的角点排序歧义是无害的。** 实测 `findChessboardCornersSB` 返回的角点顺序
   与本工具的 object points 之间只差一个**固定**的板内重标号，不同位姿下的离散度
   只有 1.5 mm / 0.64°，会被 `T_eef_camera` 吸收。所以 11×8 还是 8×11 都可以。

4. 相机内参**实时从 RealSense 厂家 profile 读取**，不读配置文件。
   本机实测：D405 序列号 `260322276846`，640×480 下
   `fx=394.43 fy=393.42 cx=318.93 cy=250.70`，与 `configs/scene.yaml` 里写的一致 ✅
   设备报 `inverse_brown_conrady`，程序会先把角点转成无畸变像素再送 `solvePnP`。

## 已知阻塞

项目文档 `docs/o10_wrist_hand_eye_calibration.md` 记录了一个硬件问题：

```
Motor 1 init failed, expected 38 params, got 35
```

这是 AIRBOT SDK 与电机固件参数数量不兼容。若出现，本程序会在
`连接机械臂 can0…` 那一步报错并提示；此时：

- 加 `--no-arm` 仍然可以采图（可用于相机内参标定），但**没有关节角就无法做手眼**
- 加 `--require-arm` 则会直接退出而不是降级
